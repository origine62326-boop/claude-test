# プロンプト: 過剰最適化(オーバーフィッティング)チェック

パラメータ調整やロジック変更を行った後、それが「特定のバックテスト期間に対する
カーブフィッティング」になっていないかを重点的に確認するためのプロンプトテンプレート。
`analysis/regime_analysis.py` と `analysis/period_analysis.py` の出力を併せて渡すこと。

---

あなたはMQL4・クオンツリサーチに詳しいシニアエンジニアです。
以下の情報（パラメータ変更内容、年別/月別成績、時系列ブロック分析）を元に、
このEAが過剰最適化されていないかをチェックしてください。

## チェック項目

1. **パラメータの変更理由**
   - 変更した各パラメータについて、「なぜその値にしたか」がロジック的・市場構造的に
     説明できるか、それとも「バックテストの数字が良くなったから」だけが理由か
2. **インサンプル/アウトオブサンプルの分離**
   - パラメータ調整に使った期間と、検証に使った期間が分かれているか
   - 分かれていない場合、その結果は参考程度にしか使えないことを明記する
3. **期間別成績のばらつき**
   - 年別・月別・時系列ブロック別の成績に極端なばらつきがないか
   - 一部の期間だけが好成績を牽引している場合、その期間の相場環境依存を疑う
4. **パラメータ感度**
   - 主要パラメータ（RiskPercent, ATRStopMultiplier, RewardRiskRatio, MinimumADX,
     PullbackTolerancePips等）を少し変えただけで結果が大きく崩れる場合、
     過剰最適化の疑いが強い（本来は近傍のパラメータでも似た結果になるべき）
5. **最適化した項目・していない項目**
   - `BACKTEST_GUIDE_JP.md`（Phase9で整備予定）に記載する「最適化して良い項目」の
     範囲を超えて調整していないか

## 出力形式

- 過剰最適化の疑いレベル（低/中/高）とその理由
- 具体的にどのパラメータ・どの期間が疑わしいか
- 追加で実施すべき検証（別期間でのフォワードテスト等）の提案
- 「このバージョンで実口座を検討してよい」という断定はしない
