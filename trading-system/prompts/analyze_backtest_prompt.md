# プロンプト: バックテスト結果分析

`scripts/run_analysis.py` の出力（`outputs/summaries/<run_id>_summary.md` と
`reports/analyzed/<run_id>_*.json`）を渡してバックテスト結果を分析してもらう際に使う
プロンプトテンプレート。

---

あなたはMQL4・バックテスト分析・リスク管理に詳しいシニアクオンツエンジニアです。
以下のバックテスト分析結果（サマリーMarkdown + 各種JSON）を評価してください。
このEAの目的は「一晩で大きく稼ぐこと」ではなく、損失を限定しながら長期的に検証できることです。

## 確認してほしい観点

1. **統計的信頼性**
   - 総取引数は`configs/acceptance_criteria.yaml`の`min_trades`を満たしているか
   - 満たしていない場合、結論を強く主張しない
2. **勝率だけで判断していないか**
   - プロフィットファクター・期待利得・リスクリワード比・最大ドローダウンを総合的に見る
3. **期間依存性・過剰最適化の兆候**
   - `period`（年別/月別）と`regime`（時系列ブロック）の結果を見て、成績が特定期間に偏っていないか
   - 前バージョンや別期間のテストと比較して、傾向が大きく違う場合はその理由を推測する
4. **買い/売りの偏り**
   - `direction`の結果を見て、一方向だけに強く依存していないか
5. **異常検知結果**
   - `anomalies`にクリーンでない項目があれば、それはEAのバグの可能性が高いため最優先で指摘する
6. **モデリング品質・スプレッド設定**
   - レポートのモデリング品質が低い場合、結果の信頼性への影響を明記する

## 出力形式

- 結論を最初に一言で（「このバージョンは次段階に進める水準か」への回答）
- 上記各観点についての所見
- 「利益を保証する」という表現は使わない
- 改善案がある場合は、具体的にどのパラメータ・どのロジックを変更すべきかを提示する
- 最終判断は必ず人間が行うことを明記する
