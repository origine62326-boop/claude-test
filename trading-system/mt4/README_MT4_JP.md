# MT4側の使い方（バックテスト結果のエクスポート手順）

このフォルダのEA (`USDJPY_LowRisk_Trend_EA.mq4`) 自体の導入・コンパイル・バックテスト実行手順は、
プロジェクトルートの `USDJPY_LowRisk_Trend_EA/README_JP.md`（Phase9で整備予定）を参照してください。

このドキュメントでは、**バックテスト結果をPython分析パイプラインへ渡すためのエクスポート手順**のみを
説明します。ここで説明する手順どおりに保存しないと、`analysis/parse_mt4_report.py` /
`analysis/parse_mt4_trades.py` が正しく読み込めません。

## 前提

Claude（このパイプラインの分析担当）は、あなたのPC上のMT4に直接アクセスできません。
そのため、MT4→Python分析の橋渡しは以下の手動ステップになります。

```
MT4でバックテスト実行
  ↓
「レポート」タブと「操作履歴」タブをそれぞれHTML保存
  ↓
2つの.htmファイルを reports/raw/ に置く（またはチャットにアップロード）
  ↓
Pythonが解析
```

## 手順

### 1. サマリーレポートのHTML保存

1. ストラテジーテスターでバックテストを実行
2. 「**結果**」タブに切り替える（グラフではなく、数値の一覧が出る画面）
3. 一覧の上で右クリック → 「**レポートを保存**」（または「名前を付けて保存」）
4. ファイル名は以下の命名規則で保存することを推奨します：

   ```
   report_<EA名>_<開始日>_<終了日>_<初期証拠金>.htm
   例: report_USDJPY_LowRisk_Trend_EA_20250721_20260721_100000.htm
   ```

5. 保存先はいったんデスクトップ等で構いません。後でこのチャットにアップロードするか、
   このリポジトリの `reports/raw/` に配置してください。

### 2. 個別トレード明細のHTML保存

1. 「**操作履歴**」タブに切り替える（1トレードごとの明細が出る画面）
2. 一覧の上で右クリック → 「**レポートを保存**」
3. ファイル名の命名規則：

   ```
   trades_<EA名>_<開始日>_<終了日>_<初期証拠金>.htm
   例: trades_USDJPY_LowRisk_Trend_EA_20250721_20260721_100000.htm
   ```

### 3. reports/raw/ への配置

2つの `.htm` ファイルを `trading-system/reports/raw/` に置きます（このチャットにアップロードして
いただければ、Claude側で配置します）。

## 注意点

- MT4のUIが日本語表示の場合、エクスポートされるHTMLのラベルも日本語になります。パーサーはこれを
  前提に作られています。もし英語UIで運用している場合は、その旨を伝えてください（パーサーの対応が必要です）。
- **重要**: このパーサーは実際にMT4から出力されたファイルでまだ検証していません（`TODO.md` 参照）。
  最初の1回は必ず実ファイルを共有し、正しく解析できるか確認してください。
- 複数のバージョン・複数の期間でテストする場合は、ファイル名を変えて全部 `reports/raw/` に
  残しておくと、後で `compare_versions.py` での比較がしやすくなります。

## EA側の注意点（Phase5-1: 日次損失上限・連敗制限）

- **口座履歴（Account History）タブの表示範囲を「全履歴」、または少なくとも当日を含む期間に
  設定してください。** MT4の`OrdersHistoryTotal()`（EAが取引履歴を読む仕組み）は、この表示範囲に
  含まれる取引しか参照できません。範囲が狭いと、当日の損益や連敗数が実際より少なく計算される
  可能性があります。
- **EAを初めて起動する前に、同一口座で手動取引・別Magic Numberの他EA・他通貨ペアの決済・
  入出金が当日中に発生していた場合、当日開始残高（DailyRiskReferenceBalance）の逆算値に
  その影響が混入し、正確に再現できません。** 本EA自身の損益集計は通貨ペアとMagic Numberで
  厳密に絞り込んでいるため誤りはありませんが、逆算の基準となる口座残高自体は口座全体を
  反映するため、この限界は排除できません。最も正確なのは、EAをサーバー日付の変わり目を
  跨いで継続稼働させた状態です。
- 日次損失上限は「当日ラッチ方式」です。一度到達すると、その後に含み損が回復しても
  **同一サーバー日付中は新規エントリー停止が継続**します（既存ポジションの管理は継続します）。
  翌サーバー日付になった時点で自動的に解除されます。
