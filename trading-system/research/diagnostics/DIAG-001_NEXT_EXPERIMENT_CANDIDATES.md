# DIAG-001: 次の実験候補（最大3件、診断結果に基づく）

`DIAG-001_ENTRY_EXIT_ANALYSIS.md`の判定（Primary Bottleneck=MIXED、Entry vs Exitの主論点は
INCONCLUSIVE）に基づき、次の候補を優先順位付きで提示する。**本ファイルはすべて候補であり、
まだ`experiment_id`は発行していない。** 承認された候補から1件ずつ、`BACKTEST_COVERAGE_EXPANSION_PLAN.md`
の運用ルールに従って正式発行する。

パラメータ最適化・複数フィルターの総当たりは含めない。各候補は変更点を1つに限定する。

## 候補1（最優先）: DIAG-001 Stage2の実行（H1 OHLC取得 → MFE/MAE分析）

- **原因への近さ**: 最も近い。Entry(選別力不足)かExit(TP/SL幅の設計)かというDIAG-001の主論点は、
  Stage2データなしには原理的に判定不能（`DIAG-001_ENTRY_EXIT_ANALYSIS.md`「判定」節参照）
- **変更点**: なし（新規バックテスト・パラメータ変更を伴わない。既存トレード183+195件に対する
  追加分析のみ）
- **必要なもの**: `DIAG-001_DATA_REQUIREMENTS.md`記載のUSDJPY H1 OHLC CSV（ユーザーがMT4
  ヒストリーセンターからエクスポート）
- **性質**: バックテストではなく診断の継続。OOS検証の対象ではない（既存データの再解析のため）
- **経済的意味**: 直接の損益改善効果はないが、以降のすべての改善候補（Entry系フィルターか
  Exit系パラメータ調整か）の優先順位を決める前提情報を提供する

## 候補2: Buy only / Sell only 比較実験（`EXP-005`候補）

- **原因への近さ**: DIRECTION_ASYMMETRYはStage1で**HIGH confidence**で確認済み（Rベース正規化後も
  買いPF≈1.03・売りPF≈0.40の非対称性が残存）。Stage2の結果を待たずに独立して検証可能
- **変更点**: `EnableLong`/`EnableShort`のみ（コード変更不要、EA入力パラメータの変更のみ。
  `BACKTEST_COVERAGE_EXPANSION_PLAN.md`優先3で検証済み、CC001・CC002双方に既存の入力パラメータ
  として存在することを確認済み）
- **1実験1変更点**: 遵守（`EnableShort=false`と`EnableLong=false`は別々の実験として登録し、
  同時に変更しない）
- **OOS検証可能**: 可能（`EXP-004`のCC001確定Baselineが得られ次第、同一期間で実施すればOOSではなく
  同一期間内の診断になる。真のOOSにするには別期間データが必要、`BACKTEST_COVERAGE_EXPANSION_PLAN.md`
  優先4参照）
- **経済的意味**: あり（売り側の非対称性が「売買判定固有の欠陥」なのか「たまたまこの期間の
  USDJPYが上昇バイアスだった」だけなのかを診断できる。ただし**「売りロジックを停止すべき」という
  Decisionを先取りしない**。あくまで診断目的の比較として位置づける（ユーザー指定の通り）
- **過剰最適化回避**: 2値（Long Only / Short Only）の比較のみで、閾値探索や複数パラメータの
  同時調整は行わない

## 候補3: ポジションサイジング歪みの深掘り分析（既存データの追加解析、新規バックテストなし）

- **原因への近さ**: POSITION_SIZINGはStage1で**副次的要因（MEDIUM confidence）**と判定済み
  （$ベースPFとRベースPFの差は0.06〜0.09で、主因ではない）。優先度は候補1・2より低い
- **変更点**: なし（新規バックテスト不要。既存の183+195トレードを、キャップの強さ
  （`理論ロット / MaximumLot`の比率）で分位分割し、キャップが強いトレードほど実現Rが悪化するか
  どうかを追加集計する）
- **1実験1変更点**: 該当（分析のみで実験ではないが、追加する集計軸は1つに限定する）
- **OOS検証可能**: 該当なし（既存データの再解析のため）
- **経済的意味**: 限定的。仮にキャップの強さと成績に相関があっても、それ自体はPF<1.0を説明しない
  （Stage1で確認済み）ため、優先度は低いままとする
- **過剰最適化回避**: パラメータ変更を伴わないため該当リスクなし

## 明示的に候補化しなかったもの

- **ADX/ATRレジームフィルター、上位足確認、時間帯フィルター等のEntry系新機能**: Stage1の
  INCONCLUSIVE判定により、これらが本当に有効な方向性かどうかStageT2結果なしには判断できない。
  候補1(Stage2)の結果を見てから改めて提案する
- **TP/SL幅の再設計、固定2Rからトレーリングへの変更等のExit系変更**: 同上の理由でStage2結果待ち
- **Long/Short別パラメータの導入**: ユーザーの明示的な禁止事項に従い候補化しない（候補2はあくまで
  診断目的の停止/非停止比較であり、方向別に異なるTP/SL等を導入するものではない）
