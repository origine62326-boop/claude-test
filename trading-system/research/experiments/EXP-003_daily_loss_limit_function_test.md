## この実験の性質（重要）

**本実験は収益性評価には使用しない。** PF・純利益・最大DD等の取引成績は参考値として記録するが、
採否の主判定には使わない。目的はただ一つ、「`MaxDailyLossPercent`による新規エントリー停止・
日付変更時のリセット・翌日の正常再開が、コードの意図通りに動作するか」という**機能そのものの
実動作確認**である（`EXP-002`のExpertsログ解析で、連敗制限機能はVERIFIEDと確認できた一方、
日次損失上限機能は本バックテスト期間中に一度も到達せずNOT_TRIGGEREDのまま残っていたことへの対応、
`EXP-002`「Expertsログ解析結果の反映」節参照）。

## 候補値算出の根拠（参考記録、確定値は上記「承認記録」参照）

`DS004`（`EXP-002`使用データ、既存の実トレード196件）から、決済時刻ベースで日次損益を再集計し、
各日の始値時点残高に対する損失率を算出した（`reports/normalized/EXP-002_run001_trades.json`の
`profit`と`close_time`を使用。EA実装の`GetTodayRealizedNet()`と同様に、決済時刻の属する暦日ごとに
実現損益を合算する方式）。**この試算は決済済みトレードの実現損益のみを集計したものであり、EA実装が
判定に含める含み損部分(`GetFloatingLossOnly()`)は含んでいない。含み損を含めると実際の到達タイミングは
本試算よりわずかに早まる可能性がある。**

| 日次損失率のしきい値X | 本データで到達したと推定される日数 |
|---|---|
| 0.10% | 91日 |
| 0.15% | 78日 |
| 0.20% | 52日 |
| 0.25% | 24日 |
| 0.30% | 14日 |
| 0.40% | 4日 |
| 0.50% | 1日（2025-09-09、-0.5482%が本データ中の最悪日） |
| 0.75%以上 | 0日 |

参考: 実際に連敗制限が発動した2026-05-14は日次実現損益-0.3300%、2026-06-17は-0.2708%だった
（いずれも3連敗が同一日に収まったケース）。

提示した3案（A=0.5%/1日程度、B=0.3%/14日程度、C=0.2%/52日程度）のうち、複数回の発動・再開サイクルを
確認できる見込みがあり、かつ既定値(2.0%)から見て不自然に低すぎない範囲であることから**B案（0.3%）を
推奨し、ユーザーが承認した**。「本試算通りに再現される保証はない」点に注意（新規エントリーが一度でも
止まれば、その後の値動きへの追従経路がEXP-002とは変わり、以降のトレード自体が変化しうるため。これは
EXP-002で観察された「取引数+12件・要因未特定」と同種の効果であり、本試算は「変化がないと仮定した場合の
目安」に過ぎない）。

## 合格条件（事前登録、2026-07-31確定。結果を見た後に変更しない）

1. 日次損失制限が複数回発動する
2. 各発動日時をExpertsログで特定できる
3. 発動後、その取引日は新規注文がない
4. 日付変更時に`DailyRiskReferenceBalance`が正常に再設定される
5. 翌日の有効シグナルで正常に取引を再開する
6. 連敗制限が干渉していない（`MaxConsecutiveLosses=20`により本試験期間中に連敗制限側が発動していないこと）
7. 注文エラー、無限ループ、異常終了がない
8. レポートの取引件数とExpertsログのopen件数が整合する（`EXP-002`と同じクロスチェック手法）

純損益・PF・最大DDは参考値として記録するが、採否の主判定には使用しない。

## acceptance_criteria / rejection_criteria

- 合格条件1〜8すべてがYESであれば、日次損失上限機能を`VERIFIED`とする（`EXP-002`の連敗制限機能と
  同じ扱い）。この時点で初めて、H002全体（連敗制限+日次損失上限の両方）についてPrimary/Secondary/
  Guardrail Metricsに基づく最終判定（ADOPTED/HOLD/REJECTED、`EXP-002`参照）を検討できる
- いずれか1項目でもNOであれば、`REJECTED`ではなく`HOLD`とし、原因調査を優先する（実装バグかテスト
  設計の不備かを切り分ける。`RESEARCH_RULES.md`第3節の精神に基づき、結果を見た後に閾値を変更して
  再実行する場合は本ファイルを書き換えず新しい`experiment_id`(EXP-004以降)を発行する）
- 収益指標（PF・純利益・最大DD等）は本実験の採用/棄却の判断に使用しない

## limitations

- 「候補値算出の根拠」節の推定発動日数は、決済済みトレードの実現損益のみに基づく試算であり、含み損
  (floating loss)を含む実際の判定とはわずかにずれる可能性がある
- 新規エントリー停止が一度でも発生すると、以降の値動きへの追従経路がEXP-002とは変わるため、
  本試算の「推定発動日数」通りに再現される保証はない
- 本実験はH002の日次損失上限側の機能検証を目的とし、収益性の評価には使用しない
- **[2026-07-31追加]** 本MT4環境は操作履歴`.htm`を保存できないため、本実験ではトレード単位の明細
  （open/close個別ペアリング、日次損益の明細ベース再計算等）は得られない。合格条件1〜8は
  Report+Expertsログのみで判定可能なため実験の遂行に支障はないが、今後Phase5-1系の実験で明細ベースの
  追加分析（例: EXP-002で行った日次P&L試算のような集計）が必要になった場合は、この制約が上限となる
- コンパイル確認は`COMPILE_CONFIRMED_BY_USER_SCREENSHOT`（ユーザー自己申告のスクリーンショット確認）
  であり、機械可読なコンパイルログではない
