# Backtest Coverage Expansion Plan（候補計画、未発行）

**本文書は候補の一覧化のみを目的とし、ここに記載された実験はいずれも`experiment_id`をまだ発行していない。
人間の承認を得た候補から1件ずつ、`EXPERIMENT_TEMPLATE.md`に基づく正式な実験ファイル（`EXP-004`以降）を
個別に作成する。本文書自体の更新（候補への✅付与、優先順位変更等）は随時行うが、新しいレジストリ・
台帳としては扱わない（既存の`HYPOTHESIS_REGISTRY.md` / `research/experiments/`の枠組みで管理する）。**

対応: `RESEARCH_PLATFORM_ROADMAP.md` Phase R1完了後、Phase R5（仮説実験フレームワーク）へ向けた準備。
`EXP-003_daily_loss_limit_function_test`（Phase5-1機能試験）の完了後に、この計画から候補を選定して
実施することを想定する。

## 方針（厳守事項の再確認）

- パラメータ最適化はまだ行わない。EMA・ADX・SL・TP等のパラメータを総当たりで変える実験は本計画に含めない
- 同じデータを使った事後的な条件選択を禁止する（結果を見てから都合の良い条件を選んで独立した証拠として
  数えることをしない）
- 各実験は「比較対象・目的・変更点」を1つに限定する（1 Experiment = 1つの明確な検証目的）
- 同じ期間・同じ設定の単なる再実行は、再現性確認（`BACKTEST_REPRODUCIBILITY.md`）以外では独立した証拠
  として数えない
- 検証回数そのものではなく、**独立した期間・相場環境・機能条件のカバレッジ**を増やすことを目的とする
- Fact/Observation/Hypothesis 3層構造（`research/governance/HYPOTHESIS_POLICY.md`）が対象とする
  「新しい経済ニュース関連のHypothesis」は本計画の対象外。本計画はH001（トレンドフォロー仮説）・
  H002（リスク管理仮説）という既存の仮説系列の検証拡張であり、`HYPOTHESIS_POLICY.md`の凍結規定の
  対象には該当しない

## 検証軸

### A. 時間分割

- 年別 / 半年別 / 四半期別 / 連続期間のウォークフォワード形式
- 現在保有しているデータ範囲は`EXP-001`/`EXP-002`と同一の2025-07-21〜2026-07-27（約1年）のみ。
  年別分割は実質「1年分を年境界で切る」ことしかできず、複数年の年別比較にはさらに長い履歴データの
  取得が前提となる（現状のMT4ヒストリーデータの範囲に依存、未確認）

### B. 相場環境

- 上昇局面 / 下落局面 / レンジ局面 / 高ボラティリティ / 低ボラティリティ
- **前提条件が未整備**: 既存の`analysis/regime_analysis.py`は時系列を機械的に4分割し移動勝率を見る
  簡易分析であり、ADX/ATRに基づく実際の相場環境（トレンド/レンジ、高低ボラティリティ）の分類機能は
  **実装されていない**（`TODO.md`に既知のギャップとして記載）。この軸の実験を登録する前に、
  価格データ（OHLC）からADX/ATRベースで期間を分類するObservationを別途整備する必要がある
  （`research/governance/OBSERVATION_SCHEMA.md`に沿った決定的な計算として実装可能。EA変更は不要）

### C. 売買方向

- Buy only / Sell only / Buy & Sell
- **EA変更は不要であることを確認済み**: EA入力パラメータに`EnableLong`（既定`true`）・`EnableShort`
  （既定`true`）が既に存在する（`trading-system/mt4/USDJPY_LowRisk_Trend_EA.mq4`、
  `claude/ea-v0.3.0-risk-management`ブランチで確認、mainのCC001にも同名パラメータがある想定だが
  未確認）。`EnableShort=false`でBuy only、`EnableLong=false`でSell onlyのバックテストを、
  コード変更なしパラメータ変更のみで実行できる

### D. コスト感応度

- スプレッド5ポイント（既存のEXP-001/EXP-002と同条件） / スプレッド拡大条件
- スリッページ: 現状の取得可能性は未確認。MT4ストラテジーテスターの`Slippage`入力パラメータ
  （既定30）はEA側の許容値であり、実際のバックテスト上の約定スリッページ自体をレポートから
  取得できるかどうかは別問題。取得できない場合は`UNKNOWN`として記録し、無理に推測しない

### E. リスク管理

- Phase1-4 Baseline（`MaxDailyLossPercent`/`MaxConsecutiveLosses`機能なし、CC001） / Phase5-1既定値
  （CC002、`MaxDailyLossPercent=2, MaxConsecutiveLosses=3`） / 連敗制限のみ / 日次損失制限のみ
- 「連敗制限のみ」「日次損失制限のみ」は、CC002のパラメータで片方を実質的に無効化する
  （例: 連敗制限のみを見る場合は`MaxDailyLossPercent`を到達不可能な値、例えば99%等に設定し、
  `MaxConsecutiveLosses`のみ既定値のまま。逆も同様）ことでコード変更なしに実現できる見込み

## 候補一覧（未発行、優先順位付き）

### 優先1: EXP-003 日次損失上限の発動機能試験（完了）

- `MaxDailyLossPercent=0.3`・`MaxConsecutiveLosses=20`で2026-07-31実行完了（`EXP-003_daily_loss_limit_function_test.md`、DS005、status=`COMPLETED`）。合格条件1〜8すべてYES、日次損失上限機能=VERIFIED
- 検証軸: E（リスク管理、日次損失制限単体の機能確認）

### 優先2: Phase1-4 BaselineとPhase5-1の完全同一条件再実行比較

- 目的: `EXP-001`（現行Baseline）は使用EAビルド（CC001かCC002か）が未確認という限界を持つため
  （`EXP-001`の`limitations`参照）、`EXP-002`との厳密なA/B比較になっていない。CC001（main, Phase1-4）を
  ユーザー環境で明示的に選択・実行し、`EXP-002`と完全に同一のパラメータ・期間・スプレッド設定で
  再実行することで、初めて「リスク管理機能の有無だけが差分」という厳密な比較が成立する
- 検証軸: E（リスク管理、Baseline確定）
- 比較対象: 新規のCC001再実行 vs `EXP-002`(CC002)
- 変更点: 使用EAビルドのみ（CC001↔CC002）、他は`EXP-002`と同一に固定
- 前提: ユーザーがMT4で`main`版EA（CC001, `72ac293f71131d53cd027a2786fbfaa2b3bed19d`）をコンパイル・
  実行する必要がある

### 優先3: Buy only / Sell onlyの方向別検証

- 目的: `EXP-001`/`EXP-002`で確認された「買いPF約1.02〜1.06、売りPF約0.305〜0.313」という非対称性が、
  売買方向自体の構造的な違いによるものか、両方向が同時に1ポジション枠を奪い合う相互作用によるものかを
  切り分ける。**「Sellを無効化すれば勝てる」という結論を先取りしない**（本実験は診断目的であり、
  EA仕様変更の提案ではない）
- 検証軸: C（売買方向）
- 比較対象: `EnableShort=false`（Buy only）、`EnableLong=false`（Sell only）を、既存のBaseline
  （CC001想定、優先2の再実行データ）と比較
- 変更点: `EnableLong`/`EnableShort`のみ。他のパラメータは優先2で確定したBaselineと同一
- 依存関係: 優先2で確定したBaseline（使用ビルド・パラメータ）が前提となるため、優先2の後に実施する

### 優先4: 異なる期間での再現性確認

- 目的: 現在のデータ範囲（2025-07-21〜2026-07-27）以外の期間でも、H001/H002の観察傾向
  （非対称性、PF水準等）が再現するかを確認する
- 検証軸: A（時間分割）
- 制約: 現状保有データが約1年分のみのため、「異なる期間」を得るには、ユーザーがMT4で別期間の
  ヒストリーデータを用いてバックテストを再実行する必要がある（データの遡及可能範囲は未確認）
- 比較対象・変更点は、対象期間が確定した時点で個別に事前登録する

### 優先5: コスト感応度試験

- 目的: スプレッド条件を変えた場合にPF・期待値がどう変化するかを確認する（既存EXP-001/EXP-002は
  いずれもスプレッド5固定）
- 検証軸: D（コスト感応度）
- 制約: スリッページの実測値取得可否が未確認（上記「検証軸D」参照）。取得できない場合は
  `UNKNOWN`のまま実施する
- 比較対象・変更点は、具体的なスプレッド拡大条件が確定した時点で個別に事前登録する
